# Proposal: Clean Up Fallback and Silent Failure Data Across Local and Production Databases

## Title
Clean Up Fallback and Silent Failure Data Across Local and Production Databases

## Context & Problem Statement

TechDaily recently transitioned from defensive, error-masking mock fallbacks to a strict **"Fail Loud & Transparent"** architectural paradigm. Prior to this transition, multiple backend services intercepted Google Gemini API errors, rate limits, missing configuration keys, and deprecated model endpoints (`text-embedding-004` returning HTTP 404) by silently generating and persisting synthetic mock data into PostgreSQL.

As a direct consequence, both local development databases (`techdaily_postgres`) and the production PostgreSQL 17 database (`techdaily_postgres_prod` on Google Cloud VPS) accumulated poisoned, synthetic, or unvectorized records across five primary tables:

1. **`TermExplanationCaches`:**
   - **Poisoned Content:** Persisted boilerplate fallback text generated by `TermExplanationService.GetFallbackExplanation`:
     - English: `"The term '{term}' in {category} represents a core runtime or architectural mechanism governing system performance and data flow."`
     - Vietnamese: `"Thuật ngữ '{term}' trong {category}: Khái niệm kỹ thuật quan trọng mô tả cơ chế hoạt động nội tại và hành vi tài nguyên của hệ thống."`
   - **Vector Corruption:** Cached terms either lack vector embeddings (`Embedding IS NULL`) or contain legacy pseudo-random vectors, corrupting HNSW cosine similarity lookups during reader term clicks.

2. **`TechInsights`:**
   - **Poisoned Content:** Synthetic mock insights generated by `GeminiAiService.GenerateMockInsight()` during API failures.
   - **Signature:** Titles derived from a hardcoded list (e.g., *"Tối ưu hóa Memory Allocation trong ASP.NET Core với ArrayPool<T>.Shared"*, *"Architecting Non-Blocking Request Ingestion with System.Threading.Channels"*), slugs with randomized 6-character hex suffixes (`-[0-9a-f]{6}`), or duplicate mock entries that bypassed seed definitions.
   - **Relational Dependencies:** Tainted insights may be referenced by `UserInsightBookmarks` (`ON DELETE CASCADE`).

3. **`QuizQuestions`:**
   - **Poisoned Content:** Canned mock questions generated by `GeminiAiService.GenerateMockQuestions()`.
   - **Signature:** Question texts following deterministic templates:
     - English: `[{level}] Question #{i} on {topic}: When addressing "{aspect}", which architectural strategy is optimal?`
     - Vietnamese: `[{level}] Câu hỏi #{i} về {topic}: Khi giải quyết vấn đề "{aspect}", phương án kiến trúc nào sau đây là tối ưu nhất?`
     - Explanations containing: `### Technical Deep Dive\n- **Optimal Solution:**` or `### Phân Tích Kỹ Thuật Chuyên Sâu\n- **Phương án đúng:**`.
   - **Relational Dependencies:** Referenced by `UserQuizProgresses` (`ON DELETE CASCADE`) and optionally by `SpacedRepetitionCards` (`SourceQuizQuestionId`, `ON DELETE SET NULL`).

4. **`SpacedRepetitionCards`:**
   - **Poisoned Content:** Boilerplate flashcards generated from user highlights via `GeminiAiService.SynthesizeActiveRecallCardAsync` fallback logic.
   - **Signature:** Cards with `SourceType = 'Highlight'` where:
     - Front: Starts with `"What is the core architectural principle behind: "` (English) or `"Nguyên lý kiến trúc cốt lõi đằng sau trích dẫn trong "` (Vietnamese).
     - Back: Raw concatenation `"{note}\n\n>{quote}"` or `"{quote}"` without genuine AI synthesis.

5. **`DocumentChunks`:**
   - **Unvectorized Chunks:** Over 465 document chunks have `Embedding IS NULL` (including Day 28, 29, and 30 of the Master 30-Day curriculum and multi-chapter uploaded books).
   - **Root Cause:** Background seeders and ingestion workers attempted embedding generation against deprecated `text-embedding-004` (404), which was either swallowed or aborted after processing only the first 50 chunks, leaving chunks unindexed in PostgreSQL `pgvector`.

## Proposed Solution

We propose a comprehensive database maintenance and data hygiene operation across local and production environments:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        DATA CLEANUP & VECTOR BACKFILL WORKFLOW                         │
│                                                                                        │
│   1. PRE-CLEANUP SAFETY                                                                │
│      - Execute full database dump (pg_dump -Fc) on production                          │
│      - Run dry-run analysis to preview affected row counts without committing          │
│                                                                                        │
│   2. TRANSACTIONAL PURGE (Atomic & Idempotent)                                         │
│      ┌───────────────────────┐   ┌───────────────────────┐   ┌───────────────────────┐ │
│      │ TermExplanationCaches │   │     TechInsights      │   │     QuizQuestions     │ │
│      │ Purge boilerplate text│   │ Purge canned mocks    │   │ Purge canned mocks    │ │
│      │ & corrupted vectors   │   │ & cascade bookmarks   │   │ & cascade progress    │ │
│      └───────────────────────┘   └───────────────────────┘   └───────────────────────┘ │
│                                  ┌───────────────────────┐                             │
│                                  │ SpacedRepetitionCards │                             │
│                                  │ Purge highlight cards │                             │
│                                  │ with boilerplate front│                             │
│                                  └───────────────────────┘                             │
│                                                                                        │
│   3. CURATED CATALOG RE-SEEDING                                                        │
│      - Execute TechInsightsSeeder.SeedAsync to restore curated catalog items           │
│      - Execute CurriculumSeeder.SeedAsync to restore core curriculum records           │
│                                                                                        │
│   4. BATCHED 768-D EMBEDDING BACKFILL                                                  │
│      - Query all DocumentChunks WHERE Embedding IS NULL                                │
│      - Batch generate embeddings in chunks of 25 via gemini-embedding-001 (768-D)      │
│      - Idempotent: safe to rerun, zero unvectorized chunks remaining                   │
│                                                                                        │
│   5. POST-CLEANUP INTEGRITY VERIFICATION                                               │
│      - Verify 0 poisoned records across all 4 content tables                           │
│      - Verify 0 unvectorized curriculum chunks                                         │
│      - Execute HNSW vector similarity smoke query                                      │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### Key Pillars of the Strategy:

1. **Dual Maintenance Delivery (CLI Command & Standalone SQL Scripts):**
   - **Application Maintenance CLI:** Implement maintenance arguments in `TechDaily.Api` (`--cleanup-data`, `--dry-run`, `--backfill-embeddings`, `--batch-size=25`, `--reseed-catalog`) that leverage application domain models, EF Core configurations, and `IEmbeddingService`.
   - **Standalone SQL Scripts:** Provide `cleanup-dry-run.sql` and `cleanup-execute.sql` for operators to inspect and execute migrations directly through `psql` or Docker CLI without booting the web application.

2. **Idempotency & Transaction Safety:**
   - Every purge query is idempotent and guarded by atomic database transactions (`BEGIN ... COMMIT`).
   - The dry-run mode issues identical counting and analysis queries inside a transaction followed by an immediate `ROLLBACK`, guaranteeing zero side effects during pre-flight checks.
   - Deletion filters use strict template signatures to ensure genuine user notes, highlights, and custom questions are never touched.

3. **Curated Catalog Re-Seeding:**
   - Following the purge of mock insights, `TechInsightsSeeder.SeedAsync` is executed to ensure all 20+ genuine senior engineering insights from `tech-insights.json` are present with correct tags, benchmarks, and markdown.

4. **Batched Vector Backfill with `gemini-embedding-001` (768-D):**
   - Backfills all 465+ unvectorized `DocumentChunks` using the standardized `gemini-embedding-001` with explicit `"outputDimensionality": 768`.
   - Uses batching (chunks of 25) with exponential backoff to respect Google Generative Language API rate limits (1500 RPM / 100 QPS) and ensure complete coverage for Days 28, 29, and 30 of the 30-Day curriculum.

5. **Multi-Environment Execution Runbooks:**
   - **Local Environment:** Automated execution against `techdaily_postgres` via `run-dev.sh` / Docker CLI.
   - **Production Environment:** Secure runbook over SSH against the Google Cloud VPS PostgreSQL 17 container (`techdaily_postgres_prod`), including snapshot creation (`pg_dump`), container maintenance execution, and health validation via `GET /api/v1/system/ai-health`.

| Table | Identification Criteria / SQL Pattern | Estimated Scope | Action |
| :--- | :--- | :--- | :--- |
| **`TermExplanationCaches`** | `ExplanationText LIKE '%represents a core runtime or architectural mechanism%' OR ExplanationText LIKE '%Khái niệm kỹ thuật quan trọng mô tả cơ chế hoạt động nội tại%'` | Local: 10–50<br>Prod: 20–100 | Hard delete poisoned rows |
| **`TechInsights`** | `Slug ~ '-[0-9a-f]{6}$'` AND `Title` in mock titles list, or matching canned problem/solution snippets not present in `tech-insights.json` | Local: 5–30<br>Prod: 10–50 | Purge mock insights; cascade delete `UserInsightBookmarks`; re-seed catalog |
| **`QuizQuestions`** | `QuestionText LIKE '%When addressing "%", which architectural strategy is optimal?%' OR QuestionText LIKE '%Khi giải quyết vấn đề "%", phương án kiến trúc nào sau đây là tối ưu nhất?%' OR ExplanationMarkdown LIKE '%### Technical Deep Dive\n- **Optimal Solution:**%'` | Local: 10–60<br>Prod: 20–150 | Purge canned questions; cascade delete `UserQuizProgresses`; set null on cards |

## Risks & Mitigations

| Risk | Impact | Mitigation Strategy |
| :--- | :--- | :--- |
| **Accidental deletion of genuine user highlights or notes** | High | The purge touches only `SpacedRepetitionCards` matching exact boilerplate template text. The underlying `UserHighlights` records are never deleted or altered. |
| **Accidental deletion of curated catalog insights** | High | Purge criteria filter on randomized slug suffixes (`-[0-9a-f]{6}`) and mock title signatures. Immediate re-seeding via `TechInsightsSeeder.SeedAsync` guarantees all curated entries from `tech-insights.json` are intact. |
| **Gemini API rate limiting during batch backfill** | Medium | Backfill processes chunks in batches of 25 with small inter-batch pacing (200ms) and retry logic with exponential backoff. Chunks already vectorized are skipped. |
| **Production database downtime or transaction locking** | Medium | Dry-run previews row counts beforehand. Purge queries execute in an atomic transaction taking < 200ms. Backfill operates on small row updates without table-level exclusive locks. |
| **Data loss on production due to unexpected script errors** | Critical | Mandatory pre-execution snapshot using `pg_dump -Fc -U techdaily_user -d techdaily_db > /backup/techdaily_pre_cleanup_$(date +%Y%m%d_%H%M%S).dump` prior to any modification. |
