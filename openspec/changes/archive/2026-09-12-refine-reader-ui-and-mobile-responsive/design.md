# Technical Design: Refine Reader UI and Mobile Responsive Experience

## Context

The TechDaily frontend uses Nuxt 4 and Tailwind CSS. The root application template (`app.vue`) currently renders `AppHeader` and `AppSidebar` unconditionally on all pages. When navigating to the book reading route (`/read/[bookId]`), the reader page defines its own internal navigation bar and Table of Contents sidebar. On desktop viewports, this causes two sidebars (`240px + 320px = 560px`) and two headers to display simultaneously, squeezing the reading column. On mobile viewports (<768px), duplicate headers consume valuable vertical space, while code block copy triggers a `ReferenceError` and inline code suffers from intrusive pseudo-element backticks.

## Goals / Non-Goals

**Goals:**
- Provide a dedicated, distraction-free reading mode on `/read/*` with 100% viewport utilization.
- Implement an integrated, compact reader header supporting back navigation, book title, slice progress, theme toggle, and quiz action across desktop and mobile.
- Support an off-canvas slide-over Table of Contents drawer on mobile with automatic closure on chapter jump.
- Deduplicate chapter titles between the page H1 element and the markdown body's initial heading.
- Sanitize typography by removing default Tailwind Typography backtick pseudo-elements from inline code.
- Fix the code copy runtime bug in `useMarkdownRenderer.ts`.
- Standardize slice terminology across English and Vietnamese locales ("Slice X of Y" / "Lát cắt X / Y").

**Non-Goals:**
- Modifying backend API contracts, database schema, or PDF extraction pipeline.
- Altering the SM-2 flashcard review or interview quiz state machines.

## Decisions

### 1. Conditional Layout Chrome in `app.vue`
- **Approach**: Compute `isReaderMode = computed(() => route.path.startsWith('/read'))` in `app.vue` to conditionally hide `AppHeader` and `AppSidebar`.
- **Rationale**: Nuxt 4 handles route matching seamlessly in `app.vue`. Hiding the global chrome for `/read/*` frees all horizontal and vertical screen space for the reader without requiring complex layout transitions or risking SSR hydration mismatches.
- **Alternative Considered**: Defining a separate `layouts/reader.vue`. While viable, `app.vue` is already the primary shell; using a reactive route check preserves clean state and requires fewer files.

### 2. Heading Deduplication in `[bookId].vue`
- **Approach**: Create a computed property or pre-render filter that checks if the markdown begins with `# {title}` or `## {title}` (case-insensitive, trimming leading `#` and whitespace). If the first heading matches `currentChunk.chapterTitle`, strip the redundant heading line before passing text to `renderMarkdown`.
- **Rationale**: Keeps the page H1 semantically anchored above the content alongside the reading time and slice badge, while eliminating unsightly duplicate headings.
- **Alternative Considered**: Omitting the page H1 entirely and letting Markdown render the title. Rationale against: Markdown chunks often start with different heading levels (`#`, `##`, `###`) or have no heading at all (e.g. raw text), resulting in inconsistent typography.

### 3. Fixing Code Copy Helper Scope
- **Approach**: In `useMarkdownRenderer.ts`, update `window.__copyCode`:
  ```typescript
  window.__copyCode = (btn: HTMLElement) => {
    const rawCode = btn.getAttribute('data-code')
    const code = rawCode ? decodeURIComponent(rawCode) : ''
    if (code) {
      navigator.clipboard.writeText(code)
      // ... update button visual state ...
    }
  }
  ```
- **Rationale**: Correctly extracts the encoded code from the clicked button's `data-code` attribute rather than referencing an out-of-scope `code` variable.

### 4. Inline Code & Typography Styling
- **Approach**: Add `prose-code:before:content-none prose-code:after:content-none` to the prose container classes in `[bookId].vue`. Style inline `<code>` as subtle pills with `rounded-md bg-slate-100 dark:bg-slate-800 text-brand-600 dark:text-brand-400 font-mono text-sm px-1.5 py-0.5`.
- **Rationale**: Eliminates the browser-rendered backtick quotes generated by `@tailwindcss/typography`, providing clean, modern inline code badges similar to GitHub and Notion.

### 5. Mobile-First Touch Ergonomics
- **Approach**:
  - On viewports <768px, render the Table of Contents as an off-canvas slide-over drawer (`z-50`) with backdrop blur.
  - When the user taps a chapter, call `selectChunk(idx)` and immediately set `isMobileTocOpen.value = false`.
  - At the bottom of each slice, format the next slice button as a full-width primary action card (`w-full py-3.5`) displaying the next chapter title for easy thumb reach.
  - Ensure all code containers use `overflow-x-auto` to prevent horizontal viewport stretching.

## Risks / Trade-offs

- **[Risk] Navigation isolation in reader mode**: Hiding the global `AppHeader` removes direct access to other routes (Today, Profile, Settings).
  - *Mitigation*: The unified reader header contains a prominent `← Library` button to cleanly return to the library catalog, and includes a ThemeToggle and Quiz action button directly within the reader header.
- **[Risk] Heading deduplication over-stripping**: A chapter markdown might contain a sub-heading with similar wording.
  - *Mitigation*: Only inspect the very first heading in the markdown text; if the first line is not a heading matching the chapter title, no lines are stripped.
