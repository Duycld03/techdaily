# Proposal

## Why

While on-device synthesis (MMS-TTS) functions offline without external dependencies, CPU synthesis still takes 30–60 seconds for a full reader slice and produces monotone speech. Google Cloud Text-to-Speech provides human-like voices (Neural2/WaveNet) and sub-2-second synthesis speed with a permanent 1,000,000 character/month Free Tier. Integrating Google Cloud TTS alongside on-device synthesis with PostgreSQL audio caching gives readers near-instant, studio-quality narration while protecting monthly quota, preserving on-device offline playback as a fallback, and giving users a direct in-player toggle.

## What Changes

- **Backend Google Cloud TTS Proxy**: An ASP.NET Core endpoint (`POST /api/v1/library/chunks/{chunkId}/audio`) that delegates synthesis to Google Cloud Text-to-Speech REST API using a single server-configured API key (`Google__TtsApiKey` in `.env`), with no client-exposed credentials.
- **Two-Tier Audio Caching (PostgreSQL & IndexedDB)**: Complete MP3 audio generated by Google Cloud TTS is persisted in PostgreSQL (`DocumentChunkAudios`) keyed by `(DocumentChunkId, ContentHash, VoiceId)`. Subsequent requests for the same slice across any user reuse the cached audio from the database in <20ms, consuming zero Google quota. Once downloaded, the browser also caches it in IndexedDB for instant scrubbing and repeat listens.
- **Audio Engine In-Player Switch (Default: Google Cloud)**: A clean toggle on `ReaderAudioPlayer.vue` letting users switch between Google Cloud and On-Device (local worker) engines. Default is set to Google Cloud and persisted in `localStorage`.
- **Server Quota Guard & Proactive Disabling**:
  - The server tracks cumulative characters synthesized in the current calendar month.
  - When quota approaches the monthly threshold (e.g., $\ge$ 950,000 characters of the 1M limit), the frontend disables the Google Cloud toggle and defaults to On-Device.
  - If a user bypasses the UI (e.g. via DevTools/API manipulation), the backend strictly rejects the request with an RFC 7807 quota exhaustion error, triggering a localized toast notification and forcing the client back to On-Device mode.
- **Free-Tier Voice Selection for Google Mode**: When Google Cloud is selected, readers can choose among curated Google Cloud Free-Tier voices (Neural2/WaveNet female and male options for Vietnamese and English).
- **Copy & Icon Polishing**: Strip buzzwordy "AI" phrasing (e.g., no "Google AI" or "AI Voice", use clean "Google Cloud" or "Cloud" vs "Thiết bị" / "Device") and remove mismatched icons (such as lightning bolts/Zap), adopting clean, subtle controls.

### Modified Capabilities

## Impact

- **Backend**:
  - New domain entity: `DocumentChunkAudio` with EF Core migration and unique composite index `(DocumentChunkId, ContentHash, VoiceId)`.
  - New infrastructure service: `GoogleCloudTtsService` with `HttpClient` calling Google Cloud TTS REST API.
  - New configuration: `Google__TtsApiKey` in `.env` and `appsettings.json`.
  - New API endpoint: `POST /api/v1/library/chunks/{chunkId}/audio` (and quota status endpoint `GET /api/v1/library/audio/quota`).
- **Frontend**:
  - `frontend/components/reader/ReaderAudioPlayer.vue`: In-player engine toggle switch, clean labels (no "AI" buzzwords), subtle icons, free-tier voice dropdown for Google mode, quota-disabled state.
  - `frontend/composables/useSliceAudio.ts`: Dual-engine orchestration (Cloud HTTP vs Local Worker), two-tier caching integration.
  - `frontend/i18n/locales/{en,vi}.json`: Localized strings for engine toggle, quota exhaustion toasts, and voice names.
- **Database**:
  - New table `DocumentChunkAudios` (PostgreSQL `bytea` for MP3 bytes, TOAST-compressed).
- **Dependencies**: No external SDK dependencies; uses ASP.NET Core `HttpClient` and native browser Web Audio / `<audio>` element.
